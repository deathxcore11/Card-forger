## What Version 27 changes

- **A saved run is never erased by starting another.** Descend with a run saved shows
  "You have a run in progress": resume it, or bank it as it stands and start anew.
- **A failed save is shown.** A "Not saved" bar with Try again stays until the write
  succeeds. The profile is written first; the saved run is removed only after that write is
  stored, so closing the page at any moment loses neither.
- **Each run is banked once.** The page names each run; the profile keeps the last 40 names
  and refuses one it has seen. A finished run found on disk at start-up is banked then.
- **Leaving banks the run as a loss.** A new engine action `abandon` ends the run from any
  screen. The page says what is kept before the player confirms. A run left before any duel
  was won or lost pays nothing, so starting and leaving cannot mint Memories.
- **Saved data that cannot be read is set aside**, under `<key>.unreadable`, and the page
  says so. It was thrown away before.
- **The Winnower.** The merchant cuts a card out of the deck, not the trunk: 15 Embers,
  never a bound meld, never below 34 cards. The engine id is still `scrapper`. The door
  text is part of hashed run state, so fixture run 901 was remade for the wording only.

Decisions made here, the owner may overturn: a run left before any duel pays nothing; a
deck never goes below 34; there is no leave control inside a duel (the chamber screens
have it).

## The Winnower in numbers

3,000 expert CPU runs, default switches: 39.7% clear without, 39.9% with a CPU that cuts
its weakest unbound card whenever it can afford to (`simCut`). No measurable gain for the
CPU. Whether a person values a thinner deck is Not assessed.

## Phone text sizes

Measured in a headless browser on the Version 26 page: the size text is drawn at after the
stage is scaled to the window.

| Window | Stage scale | Text under 9 px, by screen | Smallest text | Smallest control |
|---|---|---|---|---|
| 1280 x 720 | 0.80 | 0% on most screens; 8% duel, 45% Bazaar, 67% Anvil (card detail lines) | 6.2 px | 29 px |
| 915 x 412 (the Fold, sideways) | 0.46 | 92 to 96% (Gift screen 26%) | 3.5 px | 17 px |
| 800 x 360 | 0.40 | 95 to 100% | 3.1 px | 15 px |
| 390 x 844 (upright) | 0.24 | rotate notice only | | |

Command: `node tools/crucible/text-sizes.cjs <built index.html> <saves dir> 1280x720 915x412 800x360`.
It prints, for six screens at each window size, the smallest text, the share of text under
9, 11 and 13 px, and how many controls are under 32 px. This is the measure the phone layout
will be held to.

The stage is one fixed 1600-wide layout shrunk to fit. A phone needs its own layout with
fewer, larger things across the screen; shrinking cannot reach a readable size. A comment
in the page code says text never drops under a phone's minimum; that is false and goes
when the layout does.

## Sound hook

The page plays no sound. It now calls `window.LMAudio.cue(name, data, ctx)` when an audio
module has set it, for every button, every duel event as it is shown, run events, screen
changes and story scenes. A cue that throws is swallowed. The names are listed in the
comment above `cue` in `crucible/web/app.mjs`. The audio work is a separate thread on its
own branch.
