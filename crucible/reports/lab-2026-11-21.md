## What Version 27 changes

- **A saved run is never erased by starting another.** Descend with a run saved shows
  "You have a run in progress": resume it, or bank it as it stands and start anew.
- **A failed save is shown.** A "Not saved" bar with Try again stays until the write
  succeeds. The profile is written first; the saved run is removed only after that write is
  stored, so closing the page at any moment loses neither.
- **Each run is banked once.** The page names each run; the profile keeps the last 40 names
  and refuses one it has seen. A finished run found on disk at start-up is banked then.
- **Leaving banks the run as a loss.** A new engine action `abandon` ends the run from any
  screen. The page says what is kept before the player confirms. A run left before any duel
  was won or lost pays nothing, so starting and leaving cannot mint Memories.
- **Saved data that cannot be read is set aside**, under `<key>.unreadable`, and the page
  says so. It was thrown away before.
- **The Winnower.** The merchant cuts a card out of the deck, not the trunk: 15 Embers,
  never a bound meld, never below 34 cards. The engine id is still `scrapper`. The door
  text is part of hashed run state, so fixture run 901 was remade for the wording only.

Decisions made here, the owner may overturn: a run left before any duel pays nothing; a
deck never goes below 34; there is no leave control inside a duel (the chamber screens
have it).

## The Winnower in numbers

3,000 expert CPU runs, default switches: 39.7% clear without, 39.9% with a CPU that cuts
its weakest unbound card whenever it can afford to (`simCut`). No measurable gain for the
CPU. Whether a person values a thinner deck is Not assessed.

## Sound hook

The page plays no sound. It now calls `window.LMAudio.cue(name, data, ctx)` when an audio
module has set it, for every button, every duel event as it is shown, run events, screen
changes and story scenes. A cue that throws is swallowed. The names are listed in the
comment above `cue` in `crucible/web/app.mjs`. The audio work is a separate thread on its
own branch.


## Phase 2: the first run and the first guardian

Simulator only. Nothing here was played by a person. 2,000 runs each, the page's default switches.

| CPU player | Beats the first guardian | Notes |

- **Early first Gift** (lever `giftFirstXp: 10`, page switch `early`, off): the first Gift comes after the first duel
  won; later Gifts are unchanged. It does not help the novice (4 to 5.5%) or the adept. It gives the expert about 3
  points more clears. The other assistant's audit proposed it; the simulator says it is not the fix for the first
  guardian. Whether it feels better to a person is not assessed.
- **The Kiln Warden** was about 20 points harder than the Stone Sentinel at every skill level (adept 22% against 42%
  per attempt, expert 56% against 78%). Lever `bossBandBy: { kiln_warden: -350 }` levels them (adept 38.6 to 47.1%
  between -300 and -400). It is part of the `five` baseline in `crucible/web/labs.mjs`, so it is on in the playable.
- **Teaching** (page only, `crucible/web/coach.mjs`): three first lessons in the duel tray with numbered pips on the
  cards to tap: meld, fuel, and when one card is right. A lesson never shows what a meld makes. "No more lessons"
  hides them; the Rules page brings them back. A profile with more than two runs counts as taught.
- **Loss summary**: after a lost duel, up to three "What happened" lines from what the page showed, plus one line on
  the guardian's Law. A guardian not yet beaten shows one line of counsel on its door.

## Fact check of the review of Version 27 (the owner's second assistant)

Each finding was reproduced in a browser on the published Version 27 build before anything was changed.

| Finding | Verdict | What I saw on Version 27 | State |
|---|---|---|---|
| An old tab can delete a newer run | Real | Two pages of one browser profile. Page 1 banked the run and began a new one; Abandon in page 2 removed the new run. An ordinary move in page 2 wrote the old run over the new one. A profile write from the page that was behind undid the other page's bank. Nothing was paid twice, as the review said | Fixed |
| Some damaged saves still crash | Real, one case worse | An unknown phase offered Continue and stopped the page ("is not a function"). A finished run with missing tallies stopped the page at start-up. A finished run with an empty result did not crash: it was banked for 25 Memories | Fixed |
| The board lists leaning Gift offers as off | Real | `LAB_DEFAULTS` has `lean: true` | Board corrected |
| The pack promises at least 5 Memories every run | Real | A run left before its first duel pays nothing, by the Version 27 ruling | Pack corrected |

What changed:

- **Two tabs.** A new stored value (`lostmemories.runrev.v1`) says which run is stored and how many times it has been
  written. Before a tab makes a move it checks that the stored run is still the one it is showing. If not, it changes
  nothing and says "This run moved on" with one button back to the start, where Continue picks up the current run.
  Banking removes the stored run only if it is the run being banked. Each tab takes in the stored profile before it
  changes its own copy, and a `storage` event does the same as soon as the other tab writes.
- **Damaged saves.** `crucible/web/saves.mjs` holds the check: a known phase, the numbers and lists the page reads,
  cards that exist, and what each phase needs (doors of known kinds, a duel with both sides, an offer, a result with
  a reason). A run that fails is set aside under `<key>.unreadable`, never played and never banked. 702 saves written
  by earlier builds all pass it, and so does every state of six simulated runs.
- **Damage the check cannot see.** Showing the page and making a move are now guarded. If either fails the page goes
  back to the start and says so. The stored run is kept unless it could not even be shown after Continue, or failed
  a move twice running; then it is set aside. Each such fault is still reported as a page error beginning
  "recovered:", so the click bot and the checks keep counting them.

Limits: two tabs are told apart by reading shared storage, which has no lock. Two taps in two tabs within the same
few milliseconds could still collide. A person cannot do that by hand.

## The stage for a phone held sideways (Version 29)

The review of Version 27 put this second in its order of work: a landscape layout for the Fold in
which the hand, the choice of a target and the reward choices can be read. Version 28 and every
build before it drew one 1600-wide stage and shrank it, to 46% on a 915 x 412 screen.

**What changed.** A screen that is wider than tall, at least 1.6 to 1, and under 1152 px across now
gets a second stage, 1440 wide and 640 to 900 tall (`fit()` in `crucible/web/app.mjs`; the rules are
the block "A phone held sideways" at the end of `crucible/web/play.css`). It is scaled as one piece
like the wide stage, so nothing moves during play. On 915 x 412 it is drawn at 64%.

- Duel: one fixed table. Life Points left, five monster slots a side in the middle, the duel rules
  and the log right, six hand slots and the action panel along the bottom. A card on the table
  shows its picture and numbers; a tap opens the whole card. A defender lies on its side with its
  numbers upright. The attack forecast sits in the strip between the rows and no longer covers
  the rival's Life Points.
- Card rewards, guardian rewards and treasure stand side by side with each card at hand size. The
  Bazaar is one row of four cards with the price under each. A kit shows four sample cards with
  their numbers. Deck, trunk and Anvil grids are ten cards across.
- Every button is at least 3.2 stage em tall: 32.5 px on a 915 px wide screen, 28.4 px on 800.
- A card looked at closely is now shown upright on every screen size. Before, a defender opened
  from the table was drawn on its side across its own text. This is the one change to wide screens.
