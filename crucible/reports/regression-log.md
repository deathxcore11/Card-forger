# Lost Memories regression log: faults that reached the owner

Same rule as `qa/regression-log.md`, kept here because Lost Memories is a test build and not a release: every fault
that reaches the owner gets a row and a test that uses the exact input that broke. Faults found by our own fault
hunts are in the lab reports, not here.

| Date | Seen in | What broke (as reported to the owner) | Why the tests missed it | Test |
|---|---|---|---|---|
| 2026-11-20 | playable Version 21 | X-Head Cannon + Y-Dragon Head + Z-Metal Tank made XYZ-Dragon Cannon in the duel, but the Codex wrote only the first two cards, which read back as XY-Dragon Cannon (or YZ or XZ, by play order). The real three-card recipe was never written. Found by the owner's second assistant from the game pack and bundle. | The pool holds one three-material fusion and no test melded it and then read the Codex; the fuzz never checks what a Codex entry reads back as. | `test-crucible-rules.mjs`, "Codex: a three-card fusion is written with all three cards" |
| 2026-11-20 | playable Version 21 | Super Roboyarou could not be made. It and Super Robolady name the same two materials, the engine treated the pair as unordered and always made Super Robolady. Same report. | No test asked that every printed fusion can be made from its printed materials. | Same test; it now checks all 41 printed fusions that have materials |
| 2026-11-20 | playable Version 22 | After the Robo fix, a Codex saved by Version 21 read its Robo entry as Super Roboyarou, though that build had made Super Robolady. Found by the owner's second assistant; reproduced with a save written by the Version 21 engine. | The fix was tested only on entries written by the new build; no test read a save from the build before. | `test-crucible-rules.mjs`, "Codex: a save from the build before the fusion fix still means what it meant", on `fixtures/old-save-v21.json` |
| 2026-11-20 | playable Version 24 | A meld of three or more cards put the monster made half-way into the graveyard as well as the cards played: three copies of The 13th Grave left four monsters there, and Grave Call could hand the half-way monster back as a card. Present since the first engine. Found by the owner's second assistant. | Tests counted the graveyard after two-card melds only. The golden fixtures had recorded the fault as correct, so they could not flag it. | `test-crucible-rules.mjs`, "a meld sends only the cards played to the graveyard" |
| 2026-11-20 | playable Version 24 | Static Field weakened a rival monster showing 1,700 ATK while another showed 1,800. It ranked monsters by printed ATK plus bonuses and left out terrain and tempering. Same report. | The Static Field test had one rival monster on the table. | Same file, "Static Field hits the rival monster the table shows as strongest" |
| 2026-11-20 | playable Version 24 | Chain Lightning says the new meld that caused the damage gets the bonus; it went to an older, stronger monster unless Storm Needle caused it. Same report. | The Chain Lightning tests had one monster on the player's side. | Same file, "Chain Lightning pays the new meld that caused the damage" |
| 2026-11-20 | playable Version 24 | A run lost at once with nothing found paid zero Memories, though the game says every run pays. Same report (18 of 200 basic-strategy runs). | No test scored a run with no wins and no new melds. | Same file, "every run pays Memories" |
| 2026-11-21 | playable Version 25 | A draw Spell with fewer cards left than it draws took what was there with no draw event (so nothing to animate), and whether that should lose the duel was not written anywhere. Herald with an empty deck did the same. Found by the owner's second assistant. | The draw tests always had a full deck. The rule text said only "if you must draw and cannot, you lose". | `test-crucible-rules.mjs`, "a draw effect takes what the deck holds and shows it; only the start-of-turn draw can lose the duel" |
| 2026-11-21 | playable Version 25 | The page could not choose the target of a Spell: with a weak and a strong rival monster, picking Fissure and tapping the weak one opened its details, and the Spell destroyed the strong one. The engine had always accepted a target. Same for boost Spells and Equips played alone. Same report. | The engine test passed a target directly; nothing tapped the page. The click bot only checks that the page does not stick. | `tools/crucible/page-checks.cjs` (a browser taps the built page), plus "a Spell or Equip played alone goes to the monster the player chose" |
| 2026-11-21 | playable Version 25 | One attack that sprang a Trap and then revealed a veiled monster counted twice toward the Patient Trap feat, which says "attack into your veiled monsters or Traps 12 times". Same report. | The feat test used an attack that did one or the other, never both. | `test-crucible-rules.mjs`, "one attack is one step toward Patient Trap" |
| 2026-11-21 | playable Version 25 | A Piercing monster took Life Points from the rival when the defender's Bulwark stopped the destruction, though Piercing says "when it destroys a monster in defense". Same report. | Each Enchant had its own test; no test put two Enchants in the same battle. | Same file, "Piercing takes Life Points only when it destroys the defender", and "every pair of Enchants in battle does what the two texts say" (all 13 x 13 pairs, every position) |
| 2026-11-21 | playable Version 26 | Pressing Descend with a run already saved deleted that run with no warning: its Memories, duels won and feat progress were gone. Found by the owner's second assistant's Version 26 audit. | No test started a new run while one was saved. The click bot starts each save in its own fresh page. | `tools/crucible/save-checks.cjs` (a browser taps the built page; block "a new run with a run still saved"), fails on Version 26 |
| 2026-11-21 | playable Version 26 | When the browser refused to store a save (storage full or blocked) the page carried on as if it had saved; closing the page lost the run or the banked Memories. Same audit. | Every test ran with working storage. | Same file, block "storage that refuses": a "Not saved" bar with Try again, and the profile is stored before the saved run is removed |
| 2026-11-21 | playable Version 26 | Abandon deleted the run and banked nothing, and did not say so. Same audit. Fixing it showed two more: a finished run could have been banked twice by reloading at the wrong moment, and saved data that could not be read was thrown away silently. | Abandon was a page button that never reached the engine, so no engine test covered it. No test banked the same run twice. | `test-crucible-rules.mjs`, "leaving the pyramid ends the run as a loss and banks what it earned, once" and "leaving works from every screen, and a run left before any duel pays nothing"; `save-checks.cjs` blocks "Abandon" and "unreadable data"; the lever fuzz banks a copy of a run twice every 53rd step |
| 2026-11-21 | playable Version 26 | The Scrapper merchant sold "remove a card from your trunk" for 15 Embers. Trunk cards are not in the deck, so the purchase changed nothing in play. Same audit. | The Bazaar test checked that the card left the trunk, which it did. Nothing asked what the purchase was for. | `test-crucible-rules.mjs`, "the Winnower cuts a card out of the deck, within stated limits"; `save-checks.cjs` block "the Winnower" |
