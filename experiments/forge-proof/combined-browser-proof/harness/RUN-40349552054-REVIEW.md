## Local reproduction and narrow repair

The exact published fixture storage class lacks `getAlarm()`. The preserved hosting repair calls `txn.getAlarm()` when scheduling transactional cleanup. A local HTTP reproduction through the real AdmissionService returns the same 500 `fixture_request_failed`, with `TypeError: txn.getAlarm is not a function`, before native readiness or container lookup. This establishes a named startup contract defect consistent with the browser failure; CI intentionally did not retain the private fixture exception text itself.

A diagnostic-only addition of the missing method exposes a second defect: transactions neither copy the existing alarm into staged storage nor commit the staged alarm back with the data. The fix belongs to the browser fixture, not to production scheduling. The storage helper now models the required alarm read and atomic data/alarm commit/rollback behavior. Tests cover unset/existing alarms, commit, rollback, serialized transactions and the actual admission path.
